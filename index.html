Who I Am

I'm an AI automation and full-stack engineer. I build agents and automated workflows on Claude: the Claude Agent SDK, custom MCP tools and n8n, with Claude Code in my day-to-day workflow. The guardrails live in code rather than in the prompt: spend and tool-call caps, grounding checks, reviewer approval, and tests around the risky paths.

Recent builds include a voice support agent that only speaks answers it can trace to its knowledge base, a lead research agent with hard per-run limits and 162 tests, a lead triage system that ranks inbound leads as contact now, nurture or disqualify, and an n8n reporting pipeline that keeps the numbers out of the model's hands.

Day to day I'm a mobile engineer at ShareCar (CodeReset), where I rebuilt the core booking system for production scale and shipped an end-to-end KYC identity verification flow on a webhook-based architecture.

My work runs from React Native clients through Django/DRF, FastAPI and Next.js backends down to schema design in Supabase and PostgreSQL. I like the problems that sit between layers: session race conditions, WebView context loss, OTP providers that need swapping without touching the client.

Alongside that I research multimodal machine learning for health. My final-year thesis fuses ECG, retinal imaging and clinical data for hypertension detection — the first work to combine all three, with an equity-conscious design that avoids optical sensor bias across skin tones.

Previously an AI & Data Intern at Deloitte Nigeria. Graduated First Class (4.85/5.0) in Computer Science from Pan-Atlantic University in June 2026.

Demo build Voice AI

AI agent · Sep–Oct 2026

A browser voice agent for a fictional fintech's help desk: it answers from approved policy, checks account records, and books a human callback when a case needs one.

_06

Ops Reporting Dashboard

Case study Workflow automation

n8n workflow · September 2026

An n8n pipeline that pulls Sales, Delivery and People data from three systems, computes the metrics in code, and has Claude write the commentary.

  • Problem: one report, for any period, across Sales, Delivery and People data held in Google Sheets, Airtable and an internal API.
  • How it works: the dashboard triggers an n8n workflow that pulls all three sources, calculates the metrics deterministically, sends a summary to Claude for commentary, and stores the report in Supabase. The page polls and renders it.
  • Design decisions: the numbers never come from the model. If one source is down, the report still renders with those metrics labelled “unknown, not zero”. If the AI step fails, a banner says the metrics are unaffected. Stored reports are reused unless a recalculation is forced.
  • Outcome: a one-page report with 23 metrics, AI commentary and data-quality warnings for any chosen period.
